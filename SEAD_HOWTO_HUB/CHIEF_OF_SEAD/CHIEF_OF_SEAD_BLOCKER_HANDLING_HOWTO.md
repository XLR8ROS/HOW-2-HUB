# CHIEF OF SEAD BLOCKER HANDLING HOW-TO

## Timestamp
20260411 173900 EDT

## Purpose
This how-to defines how the Chief of SEAD should handle blockers during active work.

It exists to keep blockers explicit, reducible, and actionable.

## Core rule
A blocker must be named exactly.

A blocker must not be hidden behind vague language, silence, or generic delay language.

## When to use this how-to
Use this how-to when:

1. work cannot continue normally
2. a required input is missing
3. authority is missing
4. a dependency is late or unclear
5. access is missing
6. a canon conflict stops execution
7. a needed decision or approval has not been given

## Blocker statement format
When blocked, state:

1. the exact blocker
2. what task or output it blocks
3. whether the blocker is hard, soft, or deferred
4. the exact asset, decision, permission, or input needed to clear it

## Blocker types

### Hard blocker
A hard blocker stops meaningful forward movement.

### Soft blocker
A soft blocker allows limited progress, but prevents full completion or normal speed.

### Deferred blocker
A deferred blocker does not stop current work immediately, but will block later work if not handled.

## Blocker reduction rule
If the blocker can be reduced without violating authority boundaries, reduce it before or while escalating it.

Examples of blocker reduction include:

1. clarifying the undefined reference
2. collecting missing local context
3. narrowing the blocked scope
4. separating blocked work from unblocked work
5. preparing the request needed to clear the blocker

## Escalation rule
Escalate when:

1. authority is unclear
2. the missing item is controlled by another owner
3. the blocker affects timing materially
4. the blocker affects cost materially
5. the blocker creates scope confusion
6. the blocker creates risk beyond local authority

## Good blocker example
1. Blocker: GitHub MCP is unavailable in this runtime.
2. Blocks: repo creation and repo inspection.
3. Type: hard blocker.
4. Needed to clear: working MCP access or alternate approved GitHub path.

## Bad blocker example
“I’m stuck.”
“Something is wrong.”
“I can’t do it right now.”

That garbage tells nobody anything.
