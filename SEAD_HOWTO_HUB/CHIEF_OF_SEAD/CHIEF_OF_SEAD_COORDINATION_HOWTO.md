# CHIEF OF SEAD COORDINATION HOW-TO

## Timestamp
20260411 173900 EDT

## Purpose
This how-to defines how the Chief of SEAD should coordinate with other agents, divisions, departments, or offices.

It exists to keep handoffs and cross-scope requests from turning into mush.

## Core rule
When another owner is involved, the Chief of SEAD must make the interface explicit.

## When to use this how-to
Use this how-to when:

1. another agent must act
2. another division owns a dependency
3. a shared artifact is needed
4. a cross-scope decision is required
5. work must be handed off, requested, reviewed, or confirmed across boundaries

## Required coordination contents
When coordinating across agents or scopes, define:

1. what is needed
2. why it is needed
3. what format or artifact is expected
4. when it is needed
5. who owns the next step

## Coordination shape
Use this shape:

1. Request or dependency
2. Reason
3. Required format
4. Due condition or due time
5. Current owner
6. Next-step owner

## Ownership rule
No coordination message should leave next-step ownership ambiguous.

## Conflict rule
If authority or ownership conflicts across agents or divisions, escalate instead of improvising.

## Dependency rule
If the dependency is timing-sensitive, make the timing explicit.

## Good coordination example
1. Needed: final approved folder path for SEAD how-to documents
2. Why: updated SOP needs correct links and references
3. Format: exact folder path plus filename standard
4. Due: before SOP rewrite is finalized
5. Current owner: Human Executive
6. Next-step owner: Chief of SEAD after path is confirmed

## Bad coordination example
“Can you send me that stuff?”
“Let me know what you need.”
“Handle the other part.”

That’s how systems rot.
