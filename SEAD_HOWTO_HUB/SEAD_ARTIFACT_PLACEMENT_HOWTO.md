# SEAD ARTIFACT PLACEMENT HOW-TO

## Timestamp
20260411 164903 EDT

## Purpose
This how-to defines how SEAD should place engineering artifacts.

It exists so important engineering work is stored intentionally instead of getting buried.

## Core rule
If an engineering output is meant to persist, be reviewed, be reused, or guide later work, it must be placed intentionally.

## What counts as an engineering artifact
Examples include:

1. repo structures
2. operating docs
3. technical assessments
4. architecture outlines
5. implementation specs
6. dependency classifications
7. memory structure proposals
8. execution plans
9. structured technical notes
10. routing proposals
11. budget-related technical proposals
12. tool evaluations

## Placement logic
Use this logic:

1. if it is durable memory, put it with memory
2. if it is live working status, put it with state
3. if it is a finished deliverable, put it with outputs
4. if it is a governing or operating document, put it with the correct governing docs
5. if it belongs to a specific office, department, or division, place it at that layer

## Anti-burial rule
Do not leave important engineering artifacts buried in chat, scratch notes, or random temporary files.

## Naming rule
Use names that make later retrieval obvious.

Avoid vague names like:

1. notes
2. draft
3. stuff
4. temp
5. misc

## Review rule
Before treating an artifact as durable, confirm:

1. it is in the right place
2. the name is clear
3. the layer is correct
4. it can be found later
